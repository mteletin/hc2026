EXPMAIL: a real guest byte-mailbox job

This in-house CODE tape submits a finite job from the main Z80 to compute unit 1 through the existing byte-mailbox protocol. It returns a checked numeric result to BASIC; it does not transfer an M window or depend on bulk exchange. Units 2–16 are untouched. Source/regression evidence is not installed live proof.

Prerequisites

Start a fresh dedicated cold machine with bundled whole-chip HC2000 v2/IF1 ROMs and the existing hc2000-v2-paged-expansion-v1 identity: memory=paged, m-view=true, side-z80=16, turbo 1, no m-drive-bytes request or incompatible devices. Use the ordinary activation controls shipped with your release, not a debugger or CP/M. Off/default is a different fresh machine, not a live toggle. Do not reuse a unit containing another job.

The installed assets are <install>/app/examples/expansion-mailbox/ on Windows and <prefix>/examples/expansion-mailbox/ on Linux. Keep the shipped tape immutable; use a private location for your snapshot.

Ordinary native loading

  1. Enter CLEAR 32767 in BASIC. CLEAR is the physical X key at the K cursor; this keeps the BASIC stack/heap below the CODE payload.
  2. Use the cassette panel’s Insert tape… to open EXPMAIL.tap beside this guide.
  3. Enter LOAD "" CODE and press Enter, then PLAY. LOAD is J at the K cursor; quotes are SYMBOL SHIFT+P; CODE is extended mode (CAPS SHIFT+SYMBOL SHIFT together, release, then I). Bare LOAD without CODE is not this recipe.
  4. Wait for normal ROM tape loading completion and the BASIC editor’s OK. Use the ordinary deck Stop/eject control to eject the clean loaded tape before saving. Do not record over it.
  5. Enter PRINT USR 32768. PRINT is P at the K cursor; USR is extended mode then L. Expect a standalone decimal line 1001, not just the command echo.

These are Spectrum BASIC tokens, not literal pasted keyword letters. The default positional keyboard maps host Shift to CAPS SHIFT and Alt to SYMBOL SHIFT. Do not paste the word PRINT as individual letters. No host RAM load, PC edit, prepared HCS, tape acceleration or ROM patch is part of the recipe.

Genuine continuation checkpoint

  1. After the first 1001, release every key, leave no queued command and keep the clean tape ejected. Unit 1 is WaitingMailbox with counter 1; its outbox is acknowledged.
  2. Use the App’s ordinary selected-machine HCS Save control to a private EXPMAIL-R1.hcs. The fixed sixteen-unit arena requires the normal production resource admission; a refusal is a failure to report, not a reason to reduce the arena.
  3. Run PRINT USR 32768 once more: expect 1002.
  4. Use the same App HCS Load control to load EXPMAIL-R1.hcs.
  5. Run PRINT USR 32768 again: expect 1002 again, from a newly executed mailbox reply, not merely restored screen text.

Do not reload the TAP, CLEAR, reset/reload/start the job or replay round 1 between rounds or after Load. Without restoring round 1, a third call returns 9003. HCS restores the main scenario and side counter, epochs, mailbox and continuation together.

What is checked

The first call probes version 1, requires unit 1 ResetStopped, discovers nonzero epochs and performs CLEAR/LOAD, message 1 with challenge 11 hex, then START. The side sets SP=BFFF and counter zero once; its reply is 01 EE. It commits and executes WAIT (6), not Idle (7). The main waits for WaitingMailbox, reads 0C as ordinary bytes, validates ID/length/zero padding and both reply bytes, acknowledges 0D and only then returns 1001.

The second call retains the same epochs and WaitingMailbox continuation. Message 2 with challenge 22 hex wakes WAIT; the side counter is not initialized again. The checked reply 02 DD yields 1002. There is no RESET, CLEAR, LOAD, START, RESUME or REPURPOSE between rounds. Every root receipt is drained and released with control verb 5, including refusals. Polling is finite: at most 4096 QUERY transactions per round and 65535 response-ready port reads per RPC; neither wall-clock sleeps nor a host runner execute the job.

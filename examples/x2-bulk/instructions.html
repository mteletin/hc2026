X2 VGA: bulk graphics upload service

This in-house tape loads a BASIC-callable example and a bounded, main-owned X2 bulk graphics upload service using the shared Expansion DMA controller. It uploads bounded indexed images (>16 KiB, up to a full 320×240 plane of 76,800 bytes) without per-byte main-Z80 port transfers, preserving legacy console and drawing commands.

Start and load

  1. Start a new full-X5 machine with the X2 command VGA accelerator enabled. The equivalent flags are --memory paged --m-view --side-z80 16 --driver-z80 0 --x2-vga. The fresh card must be main-owned, with no other program using its ports.
  2. In BASIC enter CLEAR 32767, insert the supplied X2BULK.tap, enter LOAD "" CODE and press PLAY. Wait for the BASIC editor to return; eject the clean tape.
  3. Enter PRINT USR 32768. BASIC returns 0 on the ULA when all segments, completion verification, and presentation have completed. Then choose X2 VGA in the machine's display selector to see the completed 320×240 indexed image: one-pixel-wide vertical lines across the whole screen in the repeating colour sequence blue, red, magenta, green, cyan, yellow, white, blue (40 repeats of the 8-pixel sequence per row). Any nonzero result (1–5, 254, 255) is a refusal, timeout, or unsupported hardware, not success.

These are Spectrum BASIC tokens, not pasted keyword letters. CLEAR is X at the K cursor; LOAD is J; quotes are SYMBOL SHIFT+P; CODE is extended mode then I; PRINT is P; USR is extended mode then L. This uses ordinary tape loading, not a host memory edit.

Calling from guest code

After loading, the fixed entry points at 0x8000 allow custom guest software to control bulk uploads:

  • 0x8000: JP x2_bulk_demo — USR entry point. Runs full discovery, palette setup, 5-segment upload across arena pages 10–14, and presentation. Returns BC = 0 on success.
  • 0x8003: JP x2_bulk_discover — Queries port 0x779D. Returns A = 0 (Z set) if bulk graphics is supported, A = 4 (NZ) if unsupported.
  • 0x8006: JP x2_bulk_begin — Initiates an upload extent (DE = destination offset, HL = total bytes low word, BC = total bytes high word). Returns A = admission result (0 Accepted).
  • 0x8009: JP x2_bulk_segment — Submits one DMA segment (BC = arena physical page, DE = page offset, HL = byte count). Returns A = admission result (0 Accepted).
  • 0x800C: JP x2_bulk_wait_done — Polls port 0x779D until the segment DMA transfer finishes and acknowledges the segment. Returns A = 0 on completion.
  • 0x800F: JP x2_bulk_cancel — Cancels an active upload chain. Returns A = admission result (0 Accepted, 5 TooLate).
  • 0x8012: JP x2_bulk_ack — Explicitly acknowledges DMA terminal state (opcode 11).
  • 0x8015: JP x2_bulk_present — Presents the completed back plane at the next video boundary (opcode 5). Waits until presentation commits. Returns A = 0 on success.
  • 0x8018: JP x2_bulk_query — Latches and reads the 20-byte query receipt into x2_query_receipt. Returns A = 0 on valid receipt.

Framed Service 1 Additive Opcodes

The service extends framed service 1 on ports 0x759D and 0x769D with opcodes 8–11:

  • 8 BeginUpload: payload is 8 bytes: [destOffset:u32le, totalBytes:u32le]. Validates positive length and bounds within the 76,800-byte plane. Quiescent engine and idle DMA channel required. Fences drawing and presentation while the chain is Open.
  • 9 UploadSegment: payload is a 16-byte X0 descriptor: [ver=1, dir=1, flags=0, res=0, page:u16le, offset:u16le, count:u32le, tag:u32le]. Transfers up to 16,384 bytes from one arena page via DMA.
  • 10 CancelUpload: empty payload, matching chain tag. Aborts an Open chain and cancels queued DMA reservations. Cancelling a completed chain returns 5 (TooLate).
  • 11 AcknowledgeSegment: empty payload, matching chain tag. Acknowledges terminal DMA state (Done, Error, Cancelled, TooLate) to return the channel to Idle.

Latched Status Query (Port 0x779D)

Writing 1 to port 0x779D latches an immutable 20-byte query receipt. Subsequent reads return receipt bytes in order, then 0xFF:

  • [0] Signature: 0xB1
  • [1] ABI Version: 1
  • [2] Phase: 0 = Idle, 1 = Open, 2 = Complete, 3 = Cancelled
  • [3] Bulk Admission Result: 0 = Accepted, 1 = Busy, 2 = Invalid, 3 = TimeLimit, 4 = Unsupported, 5 = TooLate
  • [4..7] Committed Progress (32-bit little-endian)
  • [8..11] Total Requested Bytes (32-bit little-endian)
  • [12..15] Chain Tag (32-bit little-endian)
  • [16] DMA State: 0 = Idle, 1 = Programming, 2 = Queued, 3 = Done, 4 = Error, 5 = Cancelled, 6 = TooLate
  • [17] DMA Refusal: 0 = None, 1 = Busy, 2 = InvalidDescriptor, 3 = PermissionDenied, etc.
  • [18..19] Reserved (0)

Presentation Fence and Cancellation Recovery

The Present command is refused whenever the upload chain is Open or Cancelled. Once a chain is cancelled, already committed back-plane bytes remain hidden. Recovery from cancellation requires either a full-plane upload (offset 0, total 76,800), or a completed full-plane legacy Clear command which resets the upload fence to Idle.
